# 问题复盘与工程经验

> 本文整合一期、二期开发记录中的问题。示例地址、人员和数据均应视为演示信息；禁止补充真实密钥、客户数据或生产内网信息。

## 1. 效果评估：先确认尺子是否正确

### 1.1 评估集答案不完整或与来源不一致

现象：RAG 回答与原文一致，却因标准答案缺字段、混入推导备注或遗漏限定条件而被判错。

处理：

- 每题保存标准答案、可接受变体、来源文档、页码/段落、题型和是否需要计算。
- 标准答案直接由权威来源审核，不把调试备注写进答案字段。
- 边界题必须证明知识库中确实不存在答案，且问题没有机构、范围或时间歧义。

### 1.2 LLM Judge 对数值和近义表达不稳定

现象：四舍五入值、小数与百分比、语序变化被误判为错误。

处理：数值类先程序化归一化单位和精度，再按容差比较；枚举和关键词类使用规则比较；只有开放语义答案交给 LLM Judge，并保留判分理由供复核。

### 1.3 检索、生成与计算能力混为一谈

现象：需要除法或跨行计算的问题被放入纯 RAG 评估，最终分数无法反映检索质量。

处理：分别统计检索 Recall@K、答案生成正确率、边界拦截率和工具计算正确率。计算题应进入结构化数据/计算工具链路。

## 2. 文档解析与索引

### 2.1 中文 PDF 字符间出现空格

原因：PDF 字形坐标被解析器错误地转换成字符间距。

处理：优先比较 `pdfplumber` 等解析器；对中文字符间空格做保守清洗，并用原文抽样验证，避免误删英文或数字间的合法空格。

### 2.2 Excel 表头和层级丢失

现象：月份被降级为“列1/列2”，父级机构标题与数据行分离，保险表、层级表和交叉表互相误判。

根因：用“非空单元格最多的行”等单一启发式规则猜测所有表结构。

处理：

- 先识别表类型，再使用对应解析器，不追求一个规则覆盖所有 Excel。
- 每个 chunk 显式携带文件名、工作表、标题、父级机构、指标、时间、单位和原始行号。
- 对合并单元格和层级标题进行向下继承，但保留来源位置。
- 为每类表准备最小固定样例和快照测试。

### 2.3 重新入库后仍召回旧数据

原因：只追加新向量，没有彻底清除旧 collection 或切换索引版本。

处理：构建新版本索引，验证完成后原子切换；开发期至少在重建前删除旧 collection，并记录文档哈希和索引版本。

## 3. 检索策略

### 3.1 Chroma 分数方向理解错误

`similarity_search_with_score` 在当前用法中返回距离，数值越小越相似。若把它当相似度使用，阈值方向会完全相反。阈值判断必须与具体距离函数和库版本共同验证，并用一组明显相关/不相关样本做回归。

### 3.2 同机构、不同指标发生语义漂移

现象：查询“股份制商业银行总负债”，召回“城市商业银行总负债”或“股份制商业银行增长率”。

处理顺序：

1. 确保 chunk 元数据完整。
2. 对机构、指标、时间做结构化过滤或加权。
3. 评估 BM25 与向量的混合检索。
4. 最后再评估 reranker。

仅调宽或调严全局阈值无法同时解决漏召回和边界幻觉。

## 4. 意图与 Prompt

### 4.1 抽象规则过宽导致误杀

现象：“机构名称不匹配就拒答”等规则会把合法的类别名、简称或层级关系也判为不匹配。

处理：把意图、实体和技能选择分开；对关键边界提供正反例；低置信度时进入澄清，不用一个 Prompt 同时补救数据、检索和路由问题。

### 4.2 强制技能与自动路由互相污染

快捷入口可强制指定技能，但普通对话仍应由意图识别判断。强制技能只在当前请求生效，并记录来源，不能写回为长期用户意图。

### 4.3 待确认操作被新一轮意图覆盖

消息预览后，用户的“确认”“取消”或修改文案属于已有操作的后续状态，不应重新当作普通闲聊。处理前先检查会话中的待确认操作及有效期，再决定是否进入消息状态机。

## 5. 服务集成与部署

### 5.1 相对 URL 缺少协议和主机

服务端 HTTP 客户端不能像浏览器一样直接请求 `/api/chat`。容器内调用应使用完整地址和 Docker 服务名，例如 `http://java-backend:8080/...`；浏览器端相对地址则由 Nginx/Vite 代理处理。

### 5.2 容器内使用 `localhost` 连接其他服务

容器中的 `localhost` 指向容器自身。Java 连接 Redis、Java 调 Python 等地址应通过环境变量配置，并使用 Compose 服务名。

### 5.3 Docker 镜像拉取不稳定

曾出现超时、403 和 EOF。镜像加速地址具有时效性，不应在长期文档中承诺某个第三方镜像源永久可用。优先使用受信任的企业镜像仓库、固定镜像摘要和可追溯的代理配置。

### 5.4 前台启动导致终端断开后任务中止

长期服务使用 `docker compose up -d`，并通过健康检查和 `docker compose logs` 验证；不要依赖 `screen`/`tmux` 维持生产服务生命周期。

### 5.5 上传目录权限不足

不要默认将项目部署到 `/root`。使用专用低权限服务用户和应用目录，通过最小权限原则管理文件、日志和密钥。

## 6. 安全经验

- 开发默认密钥只适用于本机演示，不能提交真实值或沿用到共享环境。
- `.env` 被忽略不等于已经安全：若曾被 Git 跟踪，必须从索引和历史中处理，并轮换密钥。
- Mock 客户姓名和资产数据应明显标注为虚构；截图、评估集和日志同样需要脱敏。
- 文档中的示例 IP、域名、账户、路径和接口返回不得复制生产信息。
- 任何消息发送、客户查询或未来交易操作都必须具备鉴权、授权、确认、幂等和审计。

## 7. 排障顺序

遇到“回答错误”时按以下顺序定位：

1. 检查评估题和标准答案是否正确。
2. 检查原始文档解析结果和 chunk 元数据。
3. 确认索引版本，排除旧数据残留。
4. 查看 Top-K 召回，区分漏召回与排序问题。
5. 检查意图、实体、强制技能和澄清状态。
6. 检查生成 Prompt 与引用内容。
7. 最后再调整模型、阈值或引入新检索组件。
