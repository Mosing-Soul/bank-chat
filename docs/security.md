# 文档与 Git 安全规范

本目录默认会提交到 Git，内容必须可以公开给项目协作者。任何不确定是否敏感的信息，都先按敏感信息处理。

## 禁止提交

- API Key、Token、密码、Cookie、私钥、证书和带凭证的连接串。
- 生产/测试内网 IP、非公开域名、堡垒机信息和真实部署账户。
- 真实客户姓名、证件号、银行卡号、手机号、客户号、AUM、交易和消息内容。
- 未脱敏的运行日志、数据库、向量库、导出文件和截图。
- 银行内部制度、接口文档或业务数据，除非已获得明确的仓库发布授权。

## 本地敏感文档

确有必要保存时，放入 `docs/private/`；该目录已加入 `.gitignore`。建议只创建类似以下文件：

```text
docs/private/local-notes.txt
```

即使目录被忽略，也应优先使用密码管理器或受控文档系统保存密钥和生产资料，不把 Git 工作区当作秘密存储。

## 提交前检查

```bash
git status --short
git diff --cached
git ls-files | grep -E '(^|/)(\.env|private/)|\.(key|pem|p12|pfx)$'
```

同时搜索常见敏感字段：`api_key`、`secret`、`token`、`password`、`authorization`。搜索命中并不一定代表泄露，但必须逐项确认。

## 已误提交时

1. 立即禁用并轮换相关密钥。
2. 从当前 Git 索引中移除敏感文件。
3. 根据仓库协作情况决定是否清理历史；不要擅自改写共享分支历史。
4. 通知仓库负责人，并记录影响范围和处置结果。
